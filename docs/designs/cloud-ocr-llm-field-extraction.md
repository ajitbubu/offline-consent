# Design: Swap the recogniser first — cloud OCR behind the existing Engine seam

Generated by /office-hours on 2026-09-07

## Problem Statement

Extract the intake fields — **name, email, phone, and the paper date (`collectedOn`)** — from filled
consent forms, for the register and the downstream withdrawal / PMP system. Consent state and
purposes are **not** in scope for extraction: they already work (see Constraints).

Tesseract cannot read handwriting. It segments character by character and cursive has no gaps to
segment on. Measured: 59.3% field accuracy on *typed* text, 40 of 67 planted values `no-ocr`,
handwritten `ajitbubu` → `i1tbubu`.

**Founder decisions taken in session:**
1. Do not build a universal / trained layout model. Buy recognition instead.
2. The LLM path is an **interim bridge to a demo date**; a custom model remains the intended end
   state.
3. The demo runs on **the pilot org's blank template, hand-filled by the founder** — their exact
   layout, real handwriting, invented names, no personal data. This takes DPDP s.8(2) off the
   critical path for the demo entirely.

## Demand Evidence

- A named organisation has **committed** (contract / PO / signed pilot); their real filled scans are
  in hand for later use.
- The manual baseline — seconds for a human to key one form — is **not measured**. It remains the
  denominator of the business case.
- Training corpus is at **0 pairs**. Under decision (1) this stops being a blocker.

## Status Quo

Extraction's competitor is a person typing. `ml/README.md`: with `ML_SERVICE_URL` unset the review
screen *is* the manual entry form — one degradation path, not two. The asymmetry that governs every
choice here: a blank field costs a reviewer seconds; a confidently wrong field they skim and accept
becomes a corrupted legal record.

## Constraints

- **Consent and purposes are already solved and stay untouched.** Purposes come from
  `consent_notice_purpose.printed_label`, travel as an ordered index list, and tick state is read by
  ink density (`ml/app/tickbox.py`) — no training, works from the first form. `granted: null` is
  deliberately distinct from "found the box, empty"; collapsing them turns a failed match into a
  recorded refusal. **No model may be given consent state.** Adding "purpose" to an extracted-field
  list would also ask a model to select something mapping to a database row — the shape SEC-9
  forbids.
- **`collectedOn` is in scope and legally load-bearing.** NFR-2: a consent date that shifts by a
  timezone is a wrong compliance record. `DATE` columns are parsed as `'YYYY-MM-DD'` strings in
  `src/lib/db.ts`.
- **SEC-9 — a scan is untrusted input.** Recovered text never reaches a query, path or command; the
  extraction model never chooses a database identifier.
- **FR-17 permits Stage 1 as written.** `docs/PRD.md:204` requires "OCR tokens + layout
  classification for text, ink-density detection for tick-boxes… not an LLM." Replacing the OCR
  engine is *inside* that control. Only Stage 2 (below) would require a written, dated amendment
  with the customer's DPO.
- **DPDP s.8(2).** Any cloud vendor becomes a Data Processor for real personal data. The demo-data
  decision avoids this for the demo; production needs a DPA, DPO sign-off, and an India region
  (`asia-south1`) with short retention configured.
- **Human confirmation unchanged.** Output lands in `intake_draft.extraction`; `commitDraft()` reads
  `payload` alone; a value moves only when a reviewer accepts it.

## Premises

1. **The blocker is recognition, not architecture.** Anchor logic, `PREFILL_MIN_CONFIDENCE` (0.7,
   `src/lib/consent.ts:220`), the found-vs-empty distinction, `fields.py:37` "NEVER GUESS", and token
   banking are built and correct. **This premise is why Stage 2 is deferred, not shipped** — if the
   machine is right and only the recogniser is wrong, replacing the recogniser is the whole fix.
2. **The risk axis is generative vs discriminative, and it lives in Stage 1.** Tesseract fails as
   `i1tbubu` — visibly garbage, unacceptable to a reviewer. Any cloud handwriting recogniser is a
   sequence model and will fail as *Rajesh* for *Ramesh* — fluent, plausible, skimmed past — worst
   on exactly the 40/67 fields that today fail safe by returning nothing. **An extractive Stage 2
   does not mitigate this**; it bounds *mapping* error, not *transcription* error. The mitigation is
   measurement (Success Criterion 3) plus the bbox-highlight review UI, not architecture.
3. **The offline harness cannot measure handwriting.** `ml/scripts/field_accuracy.py:23`: *"It does
   NOT test handwriting; no synthetic fill can. Handwriting needs real filled paper."* The 59.3% is
   a typed-text score measuring field *location*. Any handwriting claim needs hand-keyed ground
   truth.
4. **No universal model.** The layout-model track is closed by decision. `CORPUS_TARGET = 50` and the
   training export are **re-scoped to an evaluation set**; the operator-facing copy on the staff page
   that currently frames reviews as collecting training data must change with it.

## Approaches Considered

- **Trained layout / universal model.** Closed by founder decision — needs a corpus that does not
  exist.
- **Self-hosted VLM on crops.** Rejected: still generative, needs a GPU (`ml` is CPU-only), does not
  reduce plausible-wrong risk.
- **Discriminative comb-cell CNN.** Cannot invent a name and stays inside FR-17, but needs thousands
  of labelled cells and only helps comb fields. Revisit once labels exist.
- **LLM reading the raw page image.** Rejected: maximum hallucination surface, no bounding boxes,
  discards the anchor machinery.
- **Stage 1 + extractive LLM, shipped together.** Deferred to phase 2 — see Recommended Approach.

## Recommended Approach

**Phase 1 (the demo): replace the recogniser only.**

1. **New `Engine` registry entry** for a cloud document OCR returning text *plus word-level bounding
   boxes* (`ml/app/engines/`). Boxes are non-negotiable: `tickbox.py` and `fields.py` both anchor on
   them. Selected by env var; the existing per-request `engine` form field enables **shadow mode** —
   run both engines on the same scan and log both — which is the cheapest way to obtain Success
   Criterion 3's baseline.
   *Note:* `get_engine` currently constructs with no arguments (`_ENGINES[key]()`); credentials,
   region and client lifecycle need somewhere to live. Small, but it is the real integration point.
2. **Correct text-layer handling.** A scanned form typically has a text layer for *printed* parts and
   pixels for *handwriting*. Use the text layer for **anchors and printed labels only**; OCR always
   runs for value regions. Never let the presence of a text layer suppress OCR. Normalise all
   geometry to the raster space at `RENDER_DPI` — never let PDF points (72dpi) and raster pixels
   coexist in one `Page`.
3. **Field scope: four fields via the existing anchor reader** — `fullName`, `phone`, `email`,
   `collectedOn`. No new extraction logic. If a better recogniser fixes accuracy, this is the whole
   change.
4. **Label log,** from day one: `{page_id, field_key, page, token_index_span, char_start, char_end,
   engine_id, engine_output, confidence, human_final_value, accepted|corrected}`. This is the
   evaluation set, the plausible-wrong measurement, and the training data for the future custom
   model. Character granularity matters — OCR splits `Ajit` into `Aj`+`it` and merges
   `Name: Ramesh` into one token; token indices alone cannot express either. Define the join rule
   per field kind (space for names, empty for phone/email). **Retention policy required:** this
   table stores raw OCR output of personal data, an NFR-1 / s.8(7) question.
5. **Failure matrix, written down.** OCR unreachable / timeout / 429 / malformed → fall back to the
   existing Tesseract engine, then to manual entry. Latency budget must fit the existing 20 s client
   timeout (`src/lib/extraction.ts`). No retry on timeout. **Log every transmission attempt, not
   every success** — a failed call may still have transmitted the scan, which is processing under
   s.8(2).
6. **Page-level abstain rule.** If mean token confidence is below a floor, or the page yields fewer
   than N tokens, return no fields and flag the scan for rescan. Without this, confident garbage
   tokens produce confident garbage fields.
7. **Confidence definition for the new engine.** Today it is `_mean_confidence(tokens)`. Keep that
   shape, and **re-calibrate the 0.7 gate for the new engine before pilot** — the threshold was
   tuned against Tesseract's distribution and does not transfer.

**Phase 2 (only if measurement justifies it): extractive LLM field mapping.**

Add the LLM *only* if the label log shows failures are **anchoring** failures (right text on the
page, wrong field) rather than **recognition** failures (text read wrong). If recognition is the
problem, Phase 1 already fixed it and Phase 2 buys nothing for a second processor, a second DPA, and
a written FR-17 amendment.

If it is justified, the design is: give the model the token list, have it return
`(page, token_index, char_start, char_end)` spans — never free text — so it can select but not
invent. Required alongside it, per the review:
- **`_names_another_person` as a post-filter on every span.** An LLM seeing the whole page has a
  *larger* wrong-span surface than the anchor reader, not smaller — it can select a nominee's,
  witness's or co-applicant's name. Commit `65c69d6` exists because that failure already happened.
- **The review screen must render the source bbox** for every model-sourced field. The claim that a
  wrong span is "visible against the page" is only true if the reviewer is shown the page.
- **Structural separation of instructions from page content**, since Stage 2 does place untrusted
  recovered text in an instruction channel.
- Spans are per-page; cross-page spans forbidden; page cap stated.
- A new `FieldResult.method` variant (currently `Literal["pattern","anchored"] | None`) plus a
  `SCHEMA_VERSION` bump and a `draft-form.tsx` render for it.

**Explicitly deferred:** DOCX and office formats. A DOCX has no handwriting, no scan and no
tick-box ink; supporting it needs either LibreOffice (a heavy system dependency contradicting
`render.py`'s "no system dependency beyond tesseract itself") or a bypass around both the `Engine`
seam and `tickbox.py` — meaning consent state cannot be read from a DOCX at all. That is a second
pipeline, not a reader. Revisit only if the pilot org actually produces filled DOCX intake.

## Open Questions

- Are the pilot's extraction failures **recognition** or **anchoring**? This decides whether Phase 2
  ever happens. The label log answers it.
- Which vendor, and can it be region-pinned to India with short retention?
- Cost per form: OCR per page × pages × volume. The business case is "beat a human typing"; nobody
  has priced either side.
- Is Document AI's document-level API being forced through a per-page `Engine.tokens(image)` seam
  acceptable, or does the protocol need a document-level method? Per-page calls multiply cost and
  latency inside the 20 s budget.
- Does this component serve only offline-consent, or the wider PMP product? Changes whether it is a
  module or a service.
- Under s.6(1), does a digital file count as evidence of consent, or must the artifact stay a scan?
  The PRD's non-goals say *"the subject is paper that already exists."*

## Success Criteria

1. Four fields (`fullName`, `phone`, `email`, `collectedOn`) extracted from the pilot org's layout
   and landing in `intake_draft`; never in `consent_artifact` without human acceptance.
2. **Field accuracy on hand-filled real-layout forms ≥ 85%**, against the 59.3% typed-text baseline
   and hand-keyed ground truth.
3. **Plausible-wrong rate above the 0.7 gate ≤ Tesseract's**, both measured on the same 20 hand-keyed
   forms via shadow mode. Establishing Tesseract's number is part of The Assignment.
4. Median seconds/form in review < the hand-keyed baseline on the same 20 forms.
5. A sampled audit of 50 committed records finds zero values traceable to an accepted bad pre-fill.
6. Every extraction produces a character-granular span label in the log, including corrections.

## Dependencies

- **Not blocked on legal for the demo** — the hand-filled-template decision removes s.8(2) from the
  demo path. Production still needs a DPA, DPO sign-off and region pinning before a real scan is sent.
- **Engineering, needs no real scan:** the engine adapter against a mock, text-layer/anchor handling,
  the label log and migration, the abstain rule, the failure matrix, and the `ML_SERVICE_URL`
  health warning.
- **Known adjacent gap:** the staff page warns only when `ML_SERVICE_URL` is *unset*
  (`src/app/staff/(authed)/page.tsx:177`); when it is set and the service is down, a reviewed scan
  banks no tokens and cannot be recovered. Fix before pilot.
- Set-based `commitDraft` remains deliberately deferred and untouched.
- **Copy change:** staff-page text framing reviews as training-data collection is now inaccurate
  (Premise 4).

## The Assignment

**Two things, in this order.**

1. **Hand-fill twenty copies of the pilot org's blank template today**, in pen, with invented names,
   phones, emails and dates. Scan them. That is your demo corpus, your evaluation set, and your
   ground truth — and it costs an afternoon with no legal dependency.
2. **Sit behind the pilot org's reviewer while they clear ten forms, and do not help them.** Time
   each one. Then hand-key twenty yourself and record your own seconds/form. Run the existing
   Tesseract engine over your twenty hand-filled scans and count how many wrong reads land *above*
   0.7 — that is the plausible-wrong baseline every later decision is measured against, and nobody
   has it.

## Engineering Review Outcomes (2026-09-07)

**BLOCKED ON A FIVE-MINUTE CHECK.** `ml/app/fields.py:771-773` discards the value whenever
the band beside a label classifies as a comb:

```python
if regions.classify(image, band, page.tokens).kind == "comb":
    tokens = []
```

That runs AFTER the engine. On a comb-cell form a better recogniser buys exactly zero,
and Phase 1 declares "no new extraction logic." Indian KYC forms use combs constantly.
**Check the pilot org's blank template for comb cells before building anything.** The answer
selects the architecture.

### Corrections to earlier claims in this document

- **"Consent and purposes are already solved and stay untouched" is FALSE.** `TODOS.md`
  records `INK_THRESHOLD = 0.08` calling a wrapped-label box at `ink_ratio` 0.100 consented:
  "a wrongly recorded consent from a single clean form." `npm run calibrate` exists to fix it.
  Do not demo consent state read by a threshold already written down as wrong.
- **TrOCR cannot be an `Engine`.** `base.py:36` is `tokens(image) -> list[Token]`; TrOCR is
  recognition-only on a pre-cropped line, no detection, no geometry. It is a Phase 2 crop-reader.
- **"One coordinate space" is asserted, not verified.** Cloud vendors auto-deskew and return
  vertices in the CORRECTED page space. A systematic offset yields boxes that are valid,
  ordered and positive-area but wrong, and tick-box ink is then measured off the wrong patch
  of paper at full anchor score. Verify against a real response before trusting decision 3.

### Live alternative, pending the comb check

Register the pilot's blank template once; align each scan to it (phase correlation, numpy,
no new system dependency); crop the four field regions and send small crops. Deletes page
concurrency, coordinate negotiation, anchoring compute cost, and solves combs by cropping
per cell. Tick-boxes keep reading the local image unchanged. Stays inside FR-17, needs no LLM.
Does not generalise to org #2 — but this path is already declared a throwaway bridge.

### Critical failure modes (no test, no error handling, silent)

1. **Comb fields blank after the engine swap** — `fields.py:772` discards them; the demo shows
   no improvement and nothing reports why.
2. **Coordinate offset from vendor deskew** — tick-box ink measured off the wrong patch at full
   anchor score, producing a recorded consent that was never given.
3. **Timeout eats the budget** — `TIMEOUT_MS = 20_000` covers upload + render + OCR + tickbox +
   fields. An 18s hang leaves the Tesseract fallback 2s, so decision 7 does not fire when it
   matters most and the app gets nothing, tick-boxes included.
