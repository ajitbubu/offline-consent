## Target operator

```
Who:       Internal data labeller at DataSafeguard (today: the founder, part-time)
Context:   152 real bank forms on disk. Needs labelled data so extraction can be
           measured and improved. No consent records wanted or involved.
Tolerance: Abandons any UI slower than the CLI they already have.
Expects:   Point at a folder, see everything, fix what the machine got wrong, export.
```

## The gap, with evidence

| Wanted | Today |

## Why it does not exist: every path ends at a consent record

`extract-batch.mjs:11-26` states the rule deliberately: *"`commitDraft()` is the only
thing in this codebase that writes a consent artifact… this script industrialises
everything up TO the human, and nothing past it."*

Traced end to end, labelling today means:

1. Upload one file (no bulk path exists)
2. Correct the extracted values on the review screen
3. The only buttons are **Commit** and **Reject**
4. `training.ts` exports `WHERE status = 'committed' AND ocr_tokens IS NOT NULL`, so a
   rejected draft discards the corrections
5. Therefore the only way to keep a label is to **Commit**, which writes to
   `consent_artifact` — a table carrying `no_update`, `no_delete` and `no_truncate`

**Labelling 152 test forms would write 152 permanent, undeletable consent records for
people who do not exist, into a register that holds legal evidence.** That is the
blocker, and no amount of UI fixes it.

The missing concept is a document you are merely *studying*.
`migrations/017_create_dataset_and_evaluation.sql` already provides it —
`dataset_document` with `origin IN ('synthetic','authorised_production')` and
`dataset_annotation` with `bounding_poly`, separate from consent entirely. It is
written, validated against a scratch database, and **not applied**.

## Recommended approach: bridge, do not build

Label Studio converts PDFs to paginated images with OCR layers, does bounding-box and
form-field annotation, self-hosts via Docker, and has a Python SDK and JSON export. It
is the thing being asked for, plus multi-user, keyboard navigation, dataset versioning
and ML-backend pre-annotation. Self-hosted keeps every scan in the building, so the
DPDP position is unchanged.

Building the equivalent — page viewer, zoom, box drawing, undo, keyboard nav, export,
versioning — would be the largest single piece of work left in this project, larger
than the Document AI integration, for a problem with a mature open-source category.
The reuse ladder in `ETHOS.md` stops at rung 1.

**What gets built instead: three adapters.**

1. **Folder → `dataset_document`.** Walk a directory, sniff magic bytes, SHA-256,
   render pages at `RENDER_DPI`, insert rows with `origin='synthetic'`. Reuses the
   existing `evidence_object` storage-key pattern; no new storage concept.
2. **Extraction → pre-annotations.** Push the engine's fields and tick-box readings in
   as Label Studio predictions so a labeller *corrects* rather than starts blank.
   This is the multiplier, and it is currently modest: measured today, 6 of 24 fields
   pre-fill and tick-box detection locates 32% of boxes on the cleanest form. Most of a
   form is still hand-work — correcting beats blank, but not by as much as it should.
3. **Label Studio export → `dataset_annotation`.** Values and bounding polys back into
   the schema, where `evaluation_run` and `extraction_metric` can consume them.

## Time to first labelled form

| Path | TTHW |
|---|---|
| Today | infinite — impossible without writing fake consent records |
| Bespoke labelling UI | weeks |
| **Label Studio + three adapters** | **~1 day** |

## Dependencies

- **Blocks on:** applying `migrations/014-017`. Nothing here is safe before
  `dataset_document` exists, because the only alternative store is the consent register.
- **Interacts with:** `scripts/extract-batch.mjs`, which already does the extract-and-store
  half and should be extended rather than duplicated.
- **Not blocked on:** Google Cloud, credentials, or the pilot org. Everything here runs
  against the 152 forms already on disk.

## Open questions

- Does Label Studio's export carry enough geometry to reconstruct `bounding_poly` in the
  page raster space, or is a coordinate transform needed? Unverified.
- Multi-user later: is labelling ever more than one person, and if so does that change
  the split/versioning model in `dataset_document.dataset_version`?
- Does the pilot org's own reviewer ever touch this tool, or does it stay internal
  forever? D1 chose internal; a later reversal would reintroduce the guardrail question.
